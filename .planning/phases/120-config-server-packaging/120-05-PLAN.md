<objective>
Make the baked-versus-slot split enforced rather than merely written down, and pin the
config-only package's packed manifest so a later layer-set change cannot ship silently.

Purpose: PKG-03 criterion 3 asks for a machine-checkable split — one byte of the spec must
move the digest and `verify` must reject the stale one, while endpoint, credentials and auth
mode surface as `ConfigSlot`s with no spec-derived slot among them. PKG-01/PKG-02 criterion 4
asks for a golden that catches a layer-set, layer-order or media-type change. The four
existing goldens pin `manifest_digest(value)` over a STRUCT, which is blind to all three
(D-12).

Output: pack-time `${VAR}` placeholder validation scoped to value slots (D-04 as amended by
D-17), the real london-tube fixtures copied in with a drift guard, and a packed-manifest
golden plus the spec-byte-change assertion.
</objective>

## Planner resolution

- **PR-04 — where D-04's placeholder validation lives.** D-04 is locked as "**`pack`**
  validates"; RESEARCH.md's Pitfall 1 recommended moving it to the caller because `toml` is a
  dev-dependency only. The locked decision wins over the research recommendation, so `toml`
  is **promoted to a runtime dependency** of `pmcp-package` and the validation lives in the
  crate. Rejected: an optional `config-validation` cargo feature — `make pmcp-package-gate`
  runs exactly ONE build configuration (`Makefile:871-877`), so a feature axis would create a
  gate blind spot on the very code that upholds "secrets never travel". `toml` is a
  15.2M-downloads/week crate audited clean in RESEARCH.md's Package Legitimacy Audit and is
  already resolved in the crate's dev tree at 0.8.23, so this adds no new supply-chain
  surface. The crate still parses NO schema — it resolves a dotted path and inspects one
  string value, so it holds no opinion about the toolkit's config shape.

## Flagged assumption (carried, not dropped)

- **`[[config_slots]]` completeness is NOT checked (research open question 2).** D-04 catches
  a declared slot holding a literal; nothing catches an environment-specific literal that no
  slot declares. A structural heuristic was considered and rejected: the fixture itself shows
  why — `base_url` is a bare literal that SHOULD be a slot, while `token_secret` is a bare
  literal that is deliberately inline and flag-guarded (`london-tube.toml:216-220`), so a
  naive "literal that looks secret implies a missing slot" check would cry wolf on the second.
  Recorded as prohibition P8 in `must_haves.prohibitions` and as threat T-120-14 in plan
  120-03. The visibility fix — rendering `required_slots` in `cargo pmcp package inspect` — is
  Phase 123's.
