<objective>
Give the baked-versus-slot split a vocabulary: two new typed `SlotType` variants for the
endpoint and the auth mode, a `config_key` naming the TOML path each slot fills, and a
`required_slots` function that enumerates everything the target environment must supply.

Purpose: PKG-03 requires endpoint, credentials and auth mode to surface as `ConfigSlot`s
that `classify` sorts and `aggregate` returns. `SlotType` has six variants today and none
fits — calling an endpoint an `LlmProvider` would read as a bug. Separately,
`detect_deviation` returns `None` for every identity-bearing slot by design, so it can never
name a credential slot and cannot be the thing that enumerates "what B must fill" (D-03).

Output: `SlotType::Endpoint` and `SlotType::AuthMode`, an exhaustive `tested_value()` with
no wildcard, `ConfigSlot.config_key`, and `src/slot/required.rs`.
</objective>

## Planner resolution

- **PR-03 — `ConfigSlot` gains `config_key: Option<String>`.** D-01 declares slots by the
  config KEY they fill and D-04 validates "the key named by a `[[config_slots]]` entry", but
  `ConfigSlot { slot: SlotType }` carries only a slot NAME (for `Secret` that is an env-var
  name like `TFL_APP_KEY`, not the TOML path `backend.auth.query_params.app_key`). Without
  the key, D-04's validation is unimplementable and `required_slots` cannot tell a target
  environment WHERE to put the value. Adding
  `#[serde(default, skip_serializing_if = "Option::is_none")] pub config_key: Option<String>`
  is additive, lands inside the same 0.2.0 break, and — because of
  `skip_serializing_if` — leaves the four existing golden digests byte-identical.
  Reversibility: costly (a serialized field on a wire type; removing it after configs adopt
  it is a format migration), but strictly additive to add.
