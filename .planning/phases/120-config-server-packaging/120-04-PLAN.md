<objective>
Make the proving fixture actually bootable: teach `pmcp-server-toolkit` to accept a
`[[config_slots]]` declaration block and to resolve a `${VAR}` reference in
`backend.base_url`, then move `london-tube.toml` to the slot-declaring, placeholder-holding
shape PKG-03 requires — with `parity_replay.rs` still green offline.

Purpose: D-18 (user decision, post-research) expands the phase to two waves because criterion
3 cannot be demonstrated honestly against a config the runtime rejects. Three independently
measured collisions block it today: `ServerConfig` is `#[serde(deny_unknown_fields)]`
(`config.rs:100-102`) so a `[[config_slots]]` block is a hard parse error;
`BackendSection.base_url` is a plain `String` with no expansion (`config.rs:443-448`) so
`"${TFL_BASE_URL}"` parses, validates, and then sends HTTP requests to a literal `${...}`;
and `parity_replay.rs:216-225` asserts the exact literal `base_url = "https://api.tfl.gov.uk"`
before string-replacing it.

Output: an additive `config_slots` field, `base_url` env-ref resolution reusing the toolkit's
single existing `parse_env_ref` chokepoint, both `london-tube.toml` copies updated, and a
shorter, less brittle parity harness.

## Locked-decision notes carried into the tasks

- **D-17 (locked, post-research).** D-04's `${VAR}` requirement is scoped to VALUE slots
  (endpoint, credentials). The auth-mode key is exempt as structural: `AuthConfig` is
  `#[serde(tag = "type")]` (`http/auth.rs:58-60`), so `type = "${AUTH_MODE}"` is an
  unparseable `unknown variant` error — no placeholder form of that key can exist. AuthMode
  stays a declared slot (PKG-03's three are unchanged); its baked value is the default and
  deviation surfaces through slot classification, not a placeholder.
- **D-18 (locked, post-research).** These toolkit changes are additive and their reversibility
  is `costly`: the `[[config_slots]]` schema becomes part of the toolkit's published config
  surface.
