<objective>
Make `ListenRegistry::register`'s duplicate check ask whether the incumbent is ALIVE, not
merely whether the key is OCCUPIED, so an ordinary `subscriptions/listen` reconnect is
never confused with a live duplicate — without reopening either of the collision defects
plan 113-14 closed.

Purpose: closing gap items 1/2/4 introduced a NEW regression that the verifier reproduced
live. `register` refuses any occupied key, and `ListenGuard` only drops when the SSE stream
future unwinds — which after an ungraceful client disconnect (mobile handoff, NAT rebind,
LB reap, `SIGKILL`) does not happen until the ~15 s keep-alive write fails plus TCP
retransmit. For that whole window a client reconnecting with the same subscription id —
and the spec defines that id as the JSON-RPC request id, which every SDK using small
integers or a stable id WILL reuse — receives `-32600 INVALID_REQUEST` at HTTP 400: the
JSON-RPC code for a structurally malformed request and the HTTP class for "do not retry",
for a condition that is purely transient server state. HTTP-04 / Success Criterion 3
requires the client half to work "correctly, including ordinary reconnects".

Output: a liveness-aware reclaim inside the SAME single `entries.write()` guard, pruning on
the rejection paths, and unit regression tests that pin the reconnect case, the
cross-principal isolation of the reclaim, and the continued survival of every property
113-14 established.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client → `ListenRegistry::register` | The `subscriptionId` half of `ListenKey` is CALLER-CHOSEN (it is the JSON-RPC request id). The `principal` half is SERVER-derived from `AuthContext.subject`, or an `anonymous_principal()` per-stream counter when no auth provider is configured. |
| co-tenants of ONE principal → each other's streams | Several tabs, a shared service account, or a token with a constant `sub` collapse onto one principal and can choose the same id. This is the half `ListenKey`'s pairing does NOT close. |
| a stale `ListenGuard` (unwinding SSE future) → a healthy successor at the same key | Teardown arrives after an arbitrary delay; generation scoping is what keeps it from reclaiming somebody else's entry. |
