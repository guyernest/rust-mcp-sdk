<objective>
Wire the server-side EGRESS half of MRTR: detect a handler's "I need more input" signal,
mint the continuation into a `requestState` token, emit `resultType: "input_required"` with
`inputRequests`, confine the whole mechanism to the three eligible methods with an
exhaustive compile-time tripwire, reject undeclared client capabilities with `-32021`, and
fix the `serverInfo` placement Phase 112 got structurally right but nested wrong.

Purpose: this is the half that makes HTTP-02 real. Phase 112 scaffolded
`ResponseDisposition::InputRequired` with an `#[allow(dead_code)]` specifically for this
plan; CLAUDE.md's zero-SATD rule means that allow must disappear when it is wired.
RESEARCH Pitfall 3 is the failure this plan must design against: `inject_v2_result_envelope`
is deliberately generic, so nothing stops `input_required` escaping onto `tools/list` unless
the DISPOSITION SELECTION is gated.
Output: the egress path, the eligibility tripwire, the capability check, and the
`serverInfo` fix.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| handler → wire | A handler-authored `_meta` signal is translated into an outbound sealed token |
| server → client (`inputRequests`) | The server drives handler invocations on the client, constrained by declared capabilities |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-113-23 | Tampering | `input_required` escaping onto a spec-forbidden method | mitigate | Disposition selection gated on an EXHAUSTIVE no-wildcard `ClientRequest` match plus the `mrtr_eligible` string table, with a drift test asserting the two agree and a compile error for any unclassified future variant (conformance `sep-2322-not-on-unsupported-requests`) |
| T-113-31 | Information Disclosure | pmcp-internal continuation state leaking on the wire | mitigate | `MRTR_SIGNAL_META_KEY` is REMOVED from `result._meta` before serialization and the continuation is only ever emitted sealed inside `requestState`; a test greps the serialized bytes for the key |
| T-113-32 | Elevation of Privilege | server requesting a capability the client never declared | mitigate | `-32021` with an object-shaped `requiredCapabilities`, all-or-nothing (never a silently pruned map); documented that `clientCapabilities` is never an authorization input |

| T-113-33 | Repudiation | partial `input_required` result with no resumable state | mitigate | A mint failure produces an internal error instead of a result; the spec's "at least one of inputRequests or requestState" obligation is asserted in the helper and tested |
