<objective>
Implement `subscriptions/listen` as an opt-in, capability-gated long-lived SSE stream, with
pmcp's stateless enterprise default advertising no subscription-delivered capability — the
configuration for which answering `-32601` is recorded conformant — and a local tripwire
enforcing the rule that advertising implies serving.

Purpose: D-13 resolves D-12. Research read the official conformance suite's gating logic
directly: a server advertising none of `tools.listChanged` / `prompts.listChanged` /
`resources.listChanged` / `resources.subscribe` may answer `subscriptions/listen` with
`-32601` and the check is SKIPPED; a server that DOES advertise one and then rejects the
method FAILS, because it claims a feature it does not serve. There is no polling shape for
change notifications anywhere in the spec, so D-11's polling-over-Tasks remains pmcp's
RECOMMENDED enterprise mechanism but is documented as an extension, not as the spec
mechanism.
Output: the subscription types, a capability-gated route, the stream, and the tripwire.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → listen stream | An unauthenticated-cost request holds a server connection open indefinitely |
| server notifications → subscriber | A notification may reach a subscriber that did not request its type |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-113-09 | Denial of Service | SSE stream exhaustion via many concurrent `subscriptions/listen` connections | mitigate | A documented per-principal and global cap on concurrent listen streams, rejecting the N+1th; the stream is OFF by default (advertise-nothing), which is also the recommended enterprise configuration under D-11 |
| T-113-34 | Information Disclosure | delivering a notification type the subscriber did not request | mitigate | The agreed filter is the INTERSECTION of requested and supported, computed once at registration; `fan_out` checks containment per entry; request-scoped `progress`/`message` are excluded by construction, not by caller-supplied config |
| T-113-29 | Information Disclosure | replay of stored events onto a listen stream | mitigate | The listen path never reads `Last-Event-ID` and never calls the replay functions; `resumability_active` is already false on v2 (plan 08) and is asserted rather than re-derived |
| T-113-35 | Spoofing | capability advertisement drifting from what is served | mitigate | ONE `advertises_subscriptions` predicate feeds both the discover projection and the listen gate, plus the `advertise_implies_serve` tripwire test covering each of the four capabilities individually |
| T-113-36 | Denial of Service | a hung or never-acknowledged stream wedging clients or CI | mitigate | The acknowledgement is the first frame by construction; keep-alive comments during quiet periods; graceful close sends the JSON-RPC result; every test stream read is bounded by a `tokio::time::timeout` |
</threat_model>
