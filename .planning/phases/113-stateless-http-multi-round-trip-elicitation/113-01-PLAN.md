<objective>
Land the three phase-wide foundations that every other Phase-113 plan consumes: the
final-spec re-verification record, the `ring` + `zeroize` dependency promotion, and the
three v2 transport error-code constants Phase 112 deliberately omitted.

Purpose: Phase 112 built the centralized error-code table but structurally omitted the v2
values pending the final schema. Phase 113 is the first phase graded by conformance and it
needs `-32020`/`-32021`/`-32022`, an AEAD primitive, and a key-scrubbing primitive. All are
cheap, all block everything downstream, and all must land before any wire byte is written.

The `zeroize` promotion is NOT optional polish: `zeroize` is currently reachable only
transitively through rustls's crypto chain, so `use zeroize::Zeroize;` in `pmcp`'s own
production code fails to compile with E0432. Plan 03 Task 1 is specified to zeroize the
decoded key buffer, and that scrub is the accepted mitigation for threat T-113-05. Without
this promotion, plans 03/06/08/09/10/11/12 cannot compile as written.
Output: `113-SPEC-RECHECK.md`, an updated `Cargo.toml`, and three new locked error-code
constants.
</objective>
