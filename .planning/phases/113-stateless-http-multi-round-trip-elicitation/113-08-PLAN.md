<objective>
Close HTTP-05's two independent obligations: SSE resumability is not offered on the v2 path
(`Last-Event-ID` is ignored, the event store is bypassed), and a response's JSON-RPC id is
always derived from the live request rather than from anything cached or replayed — the
general fix for the documented id-replay / discovery-cache bug class.

Purpose: The spec is verbatim on the first half ("Resumable SSE streams via `Last-Event-ID`
are not supported"; "A `Last-Event-ID` header: ignore it"), and the official suite has
already retired its `sse-polling` scenario for this revision. The second half is the one
that has actually bitten this project in production, and MRTR independently reinforces it:
retries MUST use a different id, so any id replay becomes immediately visible.
Output: an era-gated resumability predicate, a proven id invariant, and regression tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → transport (`Last-Event-ID`) | An attacker-supplied replay cursor selects which stored events are re-emitted |
| cached/stored response → a different caller | A retained envelope can be delivered to a caller that did not issue it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-113-07 | Spoofing | JSON-RPC id replay across callers (the discovery-cache bug class) | mitigate | Response ids re-derived from the live request at the single assembly point, backed by a `debug_assert!` and a concurrent-callers regression test with ≥8 in-flight requests |
| T-113-29 | Information Disclosure | `Last-Event-ID` replaying another caller's stored events on the stateless v2 path | mitigate | The v2 path does not read the header at all and never reaches `replay_events_after` / `replay_sse_events_from_header`; a v2 request carrying the header is served normally with no replay |
| T-113-30 | Information Disclosure | dead retention of v2 response envelopes in the event store | mitigate | The v2 path also stores nothing — storing without replaying is retained attack material with no functional benefit |
| T-113-19 | Spoofing | v1 resumability regression | mitigate | The `EventStore` trait, `LAST_EVENT_ID` constant and v1 replay code are untouched; `v1_resumability_unchanged` and the existing `tests/server_subscriptions.rs` are the guards |
</threat_model>
