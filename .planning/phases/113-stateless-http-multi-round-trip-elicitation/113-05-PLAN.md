accept-list, per-request `_meta` carrying `protocolVersion`/`clientInfo`/`clientCapabilities`,

milestone is untestable end-to-end, and Phase 117's agent/tester work has nothing to build on.

Extend the client transport's outbound request builder. Everything below is era-gated on
the transport's configured protocol version being `2026-07-28`; a v1 request must be

   about to send, using `crate::types::mrtr::logical_name_key` /

2. Emit the headers through a private `apply_v2_outbound_headers`-shaped helper that mirrors

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → network | Outbound headers and `_meta` cross an untrusted network and any intermediary/WAF |
| caller → client capability claims | The application decides which host handlers exist; the client must not let a caller over-claim |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-113-08 | Tampering | header/body desync originating at the client | mitigate | `Mcp-Method`/`Mcp-Name` are DERIVED from the body the transport is about to send, using the same `logical_name_key` table the server reads — the two cannot be constructed independently, so a desync would require corrupting the body itself |
| T-113-12 | Spoofing | client over-claiming `clientCapabilities` | mitigate | Capabilities are derived from `ClientHostRegistry` rather than caller-supplied; documented that a lying client only harms itself and that the server must never derive authorization from `clientCapabilities` |
| T-113-06 | Spoofing | a stored session id leaking into the v2 path | mitigate | `Mcp-Session-Id` is suppressed on v2 both outbound and on read-back, with a test asserting it is not emitted even when one is stored |
| T-113-20 | Denial of Service | header emission panicking on a pathological tool name or URI | mitigate | Non-panicking `HeaderValue::from_str` + skip pattern mirroring the server emitter; sentinel encoding for non-header-safe values; proptest over arbitrary method/name strings |
| T-113-21 | Information Disclosure | `_meta.clientInfo` treated as identity by a server | transfer | Self-reported and unverified by construction; the server side (plan 06) binds identity to `AuthContext.subject` only, and the existing `RequestHandlerExtra::client_info` rustdoc already carries the not-for-authorization warning |
</threat_model>
