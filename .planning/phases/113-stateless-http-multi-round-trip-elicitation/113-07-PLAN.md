<objective>
Make the pmcp `Client` fulfil MRTR: parse `inputRequests`, dispatch each entry to the
already-registered Phase-106 host handler for its kind, splice the resulting
`inputResponses` plus the echoed `requestState` into a resend with a new JSON-RPC id, and
repeat under a bounded round limit.

Purpose: CLNT-02. D-06 locks handler REUSE — one elicitation callback works on v1
(interactive) and v2 (MRTR). D-07 locks that the loop must never assume a human: an
autonomous agent's handler may satisfy `inputRequests` programmatically from other MCP
servers it holds. D-09 locks the bound. RESEARCH adds the correction that makes this
non-trivial: `inputRequests` carries THREE request kinds, not just elicitation, so the fold
is a three-way dispatch onto the existing `ClientHostRegistry`.
Output: a typed round-limit error, an `inputRequests` classifier, and the bounded loop.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server → client (`inputRequests`) | A remote server drives local handler invocations, which may reach a human or other MCP servers |
| server → client (`requestState`) | An opaque blob the client must echo without interpreting |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-113-11 | Denial of Service | a server looping the client indefinitely with `input_required` | mitigate | `mrtr_round_limit` default 8, counted per LOGICAL round; exceeding it returns `mrtr_round_limit_exceeded` WITHOUT re-invoking any handler; the `round_limit` test asserts the exact send count |
| T-113-07 | Spoofing | JSON-RPC id replay across rounds | mitigate | A fresh id is allocated every iteration (spec MUST); `retry_uses_new_id` asserts pairwise distinctness on the ids the server actually observed |
| T-113-25 | Information Disclosure | client parsing or leaking `requestState` contents | mitigate | Echoed byte-for-byte with a code comment citing the spec prohibition on inspecting/parsing/modifying; no code path deserializes it |
| T-113-26 | Elevation of Privilege | fabricating an `inputResponse` for an unregistered capability | mitigate | `FoldOutcome::CannotFulfil` is all-or-nothing: no partial map, no synthesized answer; a declined or erroring handler yields the same outcome |
| T-113-27 | Spoofing | a malicious server coaxing a human through repeated elicitation | mitigate | The bound applies identically to the human and agent shapes (D-07); the round counter is also surfaced server-side so a handler can give up early |
| T-113-28 | Tampering | MRTR fields landing in `_meta` instead of `params` | mitigate | The resend writes them through `splice_mrtr_params` only; the shared helper's tests assert top-level `params` placement |
</threat_model>
