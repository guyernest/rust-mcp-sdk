<objective>
Layer the human-in-the-loop approval hook (HOST-04) and capability derivation (HOST-05) onto the host dispatch built in plan 01, and add fuzz coverage for the inbound host-request deserialization path. Approval defaults to allow, can deny a request before a completion is returned, and denial surfaces as a JSON-RPC error rather than a connection failure. Advertised `ClientCapabilities` become truthful — the registry is authoritative for the three host fields (sampling/elicitation/roots), overriding any caller-supplied value so advertisement never lies.

Purpose: HOST-04 is the host-side access-control seam consoles/approval flows plug into; HOST-05 makes capability advertisement match actual behavior. Fuzz satisfies the ALWAYS robustness requirement for the new inbound surface.
Output: Approval invocation + capability derivation in `src/client/mod.rs`, plus a registered `client_host_dispatch` fuzz target.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server -> client (inbound sampling) | A server can push sampling requests that drive the host's LLM. The approval hook is the policy gate before a completion is returned. |
| server -> client (malformed params) | Server-controlled JSON is deserialized into typed params before dispatch. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-106-05 | Elevation of Privilege | server coerces client into an unapproved LLM call | mitigate | HOST-04 approval hook invoked before returning a completion (Task 1); Deny returns a -32603 error, default is allow (documented). This is the host-side access-control seam (ASVS V4). |
| T-106-06 | Spoofing/Repudiation | client advertises a capability it cannot honor (caller sets sampling with no handler) | mitigate | HOST-05 makes the registry AUTHORITATIVE for sampling/elicitation/roots (Task 2 — override, not merge); caller-supplied values for those three fields are discarded so advertisement matches actual behavior. Override unit test proves caller-set + no-handler => absent. |
| T-106-07 | Denial of Service | malformed inbound sampling/elicitation params panic or hang the client | mitigate | Typed serde deserialization + the client_host_dispatch fuzz target (Task 3) proving no panic on adversarial JSON (ASVS V5). |
| T-106-08 | Denial of Service | approval callback denial tears down the connection | mitigate | Deny returns a JSON-RPC error Response (not Err); the receive loop continues — unit-tested in Task 1. |
| T-106-SC | Tampering | npm/pip/cargo installs | accept | No packages installed — additive code within existing pmcp + fuzz crates (RESEARCH Package Legitimacy Audit: N/A). |
