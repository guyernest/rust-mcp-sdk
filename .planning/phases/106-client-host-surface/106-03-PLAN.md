<!-- Facts the prose must be accurate about (from the working tree + plan 01). -->

Two directions to contrast:
- LLM-server pattern (legacy, kept, NOT deprecated): `Client::create_message` (src/client/mod.rs:1846) sends `sampling/createMessage` TO a server; the server answers via its `crate::server::traits::SamplingHandler` (src/server/traits.rs:62). Direction: client -> server. Use case: the "LLM lives behind an MCP server" pattern.
- Spec host sampling (new in phase 106): a server asks the client via `sampling/createMessage`; the client answers via `crate::client::host::HostSamplingHandler` (created in plan 01). Also covers `elicitation/create` (HostElicitationHandler) and `roots/list` (roots provider). Direction: server -> client. Constraint to mention: today the client answers these only while one of its own requests is in flight (nested flow) — a pure idle host needs a background receive loop, which is deferred.

Book conventions: existing Chapter 17 pages are short stubs (e.g. ch17-03-sampling-tools.md). SUMMARY.md lists Chapter 17 sub-pages under the line "- [Chapter 17: Complete Examples](ch17-examples.md)" (~line 53) with two-space-indented `  - [Title](file.md)` entries; the last existing sub-entry is "  - [Tool with Sampling](ch17-03-sampling-tools.md)" (~line 56).
