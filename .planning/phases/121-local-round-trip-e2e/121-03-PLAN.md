  <action>
Add `roundtrip_e2e_asserts_nothing_about_manifest_shape`, a plain `#[test]`, with all four
properties below. Dropping any one of them degrades the guard into something that can pass
while measuring nothing.

**1. Read the file at compile time.** Declare a const holding `include_str!` of this test file's
own name. The argument resolves relative to the test file, so there is no runtime path
resolution and no manifest-directory join to get wrong — the same mechanism the sibling pin
tripwire uses.

**2. Scope the scan to executable assertion lines only.** A line qualifies iff its
leading-whitespace-trimmed form does NOT begin with a line-comment marker AND the line contains
the substring `assert`. This is the Rust translation of "scope to the two executable elements".
It is what lets this file's own header explain, at length, that it asserts on none of these
shapes without the guard tripping on the explanation. If the header ever trips the guard, the
line filter is wrong — do not delete the explanation.

**3. Deny-list as a named constant.** Declare a `const` array of string slices, each token
traceable to SC4's own wording ("manifest field names, layer ordering, digest values"). The
list must cover at minimum: the word for a content hash and its algorithm-prefixed form; the
indexed accessors for the manifest collection and the layer collection; the layer accessor
call; both the snake-case and camel-case spellings of the media-type field; the artifact-type
field; the blob-read and index-read accessors; and the annotations field. Keep it as data in a
named constant so it reads as a list, not as a regular expression. For each qualifying line,
assert none of the deny-list entries appears in it, with a failure message naming both the
offending token and the offending line.

**4. A nonzero-lines-scanned floor.** Count the qualifying lines and assert that count is at
least a stated floor — set it from the file's real assertion-line count minus a margin, and
comment the number so a later reader knows it was measured rather than guessed. The failure
message must say the guard is not reaching the file. Without this, a renamed file, an
over-tight filter, or an unexpected `include_str!` target makes the loop body never execute and
the test passes having examined nothing. This is the same discipline the Makefile applies to
test counts.

Give the test a doc comment stating which SC4 clause it discharges and repeating, in one line,
the self-satisfaction failure mode the comment-stripping exists to avoid.
  </action>
