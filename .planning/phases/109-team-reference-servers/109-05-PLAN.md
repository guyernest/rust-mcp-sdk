<objective>
Implement the team-mcp reference server (TEAM-05) — the worked migration template replacing the platform's raw-JSON-RPC bypass. Each roster member is a Phase 108 `AgentServer` reached over an in-memory `DuplexTransport` via a `pmcp::Client` per member (D-13). `team_mcp__<member>` dispatch validates the guards (strict depth parse, depth bound, self-call by ID, ancestor-cycle — D-14), forwards the call as a TASK-AUGMENTED `tools/call` (Pitfall 1 — plain `call_tool` drops `related_task`; use `Client::call_tool_with_task`), and re-emits the member's `CallToolResult` VERBATIM via `ToolOutput::Result` preserving top-level `_meta[related_task]`. The HTTP binary maps the `x-pmcp-team-depth` header into the namespaced `_meta` at the edge (D-14). Add the ALWAYS fuzz target over the guard/depth parser.

Purpose: Prove the real MCP hop surfaces `related_task` end-to-end — the single highest-risk deliverable of the phase and the TEAM-05 migration template.
Output: `src/team/{guards,member,server}.rs`, `src/bin/team_mcp.rs`, `tests/team_props.rs`, and a fuzz target.
</objective>

| Boundary | Description |
|----------|-------------|
| MCP client → team_mcp__<member> args + _meta | Untrusted depth/caller/ancestor guard state crosses into dispatch |
| team-mcp → member AgentServer (in-process hop) | Trusted in-process member envelope re-emitted verbatim |
| HTTP header → _meta | x-pmcp-team-depth header mapped into guard state at the edge |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-109-05-01 | Denial of Service | unbounded team recursion (missing/forged/garbage depth) | mitigate | Strict integer parse (garbage → Error, never 0) + depth>max_team_depth reject + ancestor-cycle guard; property-tested + fuzzed (Task 1). HIGH — blocking. |
| T-109-05-02 | Denial of Service | self-call / cycle loop between members | mitigate | Self-call guard (ID compare, not name) + ancestor-chain guard (Task 1/2). HIGH — blocking. |

| T-109-05-04 | Spoofing | member lookup by display name allows impersonation | mitigate | Lookup strictly by stable configured member ID; guards compare IDs (Task 1). |
| T-109-05-SC | Tampering | dependency graph | mitigate | No new registry package; `libfuzzer-sys` is fuzz-only, in the excluded fuzz sub-package; core deps are in-repo path crates. |
