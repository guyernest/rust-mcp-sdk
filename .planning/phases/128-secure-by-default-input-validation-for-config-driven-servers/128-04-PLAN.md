<objective>
Give hand-written typed tools the same value-free field validation the config path now gets, and close
the two false enforcement claims that live outside the toolkit.

Purpose: E3 is the escape hatch for teams that leave the config path. `garde` has been an optional
dependency of `pmcp` with zero references anywhere in `src/` — the same declared-but-unimplemented
shape as the toolkit's `input-validation` feature. This plan retires that. In the same pass, D-03
deprecates the third dead validation path (`src/server/validation.rs`: 11 public validators, zero
callers in `src/`) and corrects the codebase map that advertises it as live.

Output: `new_validated` constructors on both typed-tool types, a root integration test, the `s57`
example that discharges SC-8's runnable-example leg, a deprecated-and-hidden `server::validation`, and
two corrected `ARCHITECTURE.md` bullets.
</objective>

- **E3 covers BOTH `TypedTool<T, F>` and `TypedSyncTool<T, F>`.** SC-5 names only `TypedTool<T>` and
  is satisfiable either way, but RESEARCH Finding 4c measured that the same struct exists twice with

  property. Shape A costs one private field and one constructor and changes no bound.
