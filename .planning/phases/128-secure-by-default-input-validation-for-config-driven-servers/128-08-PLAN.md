<objective>
Complete D4(b) on the Code Mode surface — the spec-declared narrowing — and pin the floor-then-narrow
ordering as a property rather than as a handful of fixtures.

Purpose: plan 05 moved placeholder resolution ahead of dispatch and added a default-implemented
`placeholder_rules` hook because `PlanExecutor` has no access to an OpenAPI document. The only
component that does is the executor implementation, and `HttpCodeExecutor` does not carry the parsed
schema today — it holds a client, a base URL, an auth provider and a per-request token. This plan
gives it the schema and overrides the hook.

Output: `HttpCodeExecutor::with_schema`, the `placeholder_rules` override, the binary wiring, and a
property-test binary asserting the D-10 ordering and percent-encoding closure over generated input.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OpenAPI document (third-party, baked into a package) -> placeholder narrowing rules | It may narrow, never widen. |
| `HttpExecutor` implementor with no spec -> `placeholder_rules` default | A default that reads as "no checks" would be a silent hole. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-128-35 | Tampering | a permissive spec `pattern` disabling the floor on the Code Mode surface | high | mitigate | The floor runs unconditionally inside `validate_path_placeholder` before any declared pattern is consulted (D-10); `property_declared_pattern_never_widens_the_floor` asserts it over generated payloads rather than over a handful of fixtures, because the measured catch-all pattern accepts every CR-01 payload. |
| T-128-36 | Repudiation | the `placeholder_rules` default reading as "no checks" | high | mitigate | The default returns floored-and-capped rules and the override's rustdoc says so explicitly; a unit test asserts a schema miss still refuses a floor-denied value. |
