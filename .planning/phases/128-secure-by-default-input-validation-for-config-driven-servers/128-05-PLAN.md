<objective>
Make every `HttpExecutor` implementor safe by construction, and stop the resolved path leaking back
into the refusal one layer up.

Purpose: `HttpCodeExecutor::execute_request` calls `resolve_path` inside its own impl, so a decorator
wrapping the public `HttpExecutor` trait sees only the template the script wrote — which is what made
the UMLS team's `OutboundGuard` blind and let `api.get('/search/{a}{b}', ...)` become
`/search/2026AA?string=<380 chars>`. Moving resolution ahead of dispatch closes the class for every
implementor, in this repo and out of it, including pmcp.run's built-in `openapi-api` server — which
is how CR open question 5 is answered by construction rather than by asking a platform team to adopt.

Output: a `ResolvedPath` newtype that makes the contract change a compile error rather than a silent
semantic shift, layer-2 resolution moved into `PlanExecutor`'s two `ApiCall` arms with
`validate_path_placeholder` on each value, the two path-echoing error wraps fixed, the toolkit's
`execute_request` stripped of its step (1), and the three Code Mode CR-01 probes.
</objective>
