<objective>
Ship the tasks-aware tool seam implementation and the package-config resolution seam:

1. **`ClientToolInvoker` (AGNT-08):** implements `ToolInvoker` over `pmcp::Client`. `invoke_batch` dispatches in parallel via `futures::join_all` (D-07); each call reads `related_task` and, when present, drives the task to completion via `Client::wait_for_task` (which wraps `poll_decision`, SEP-1686). Long tool calls surface as pollable state — don't hand-roll the poll loop.
2. **`SlotResolver` seam + two impls (AGNT-09):** resolves an `AgentPackage`'s config slots (D-14) — an env-var-convention resolver and an explicit programmatic builder. Deviation from a slot's `tested_value` warns and runs (D-15). Connector refs resolve via an endpoint map (name → URL/command) the resolver supplies (D-16); the invoker connects `pmcp::Client`s from that map.

Purpose: these two seams complete the "same definition drives laptop, deploy targets, and platform" story — config resolution is host policy (a seam), and the invoker consumes the task-augmented contract the adapter (plan 108-06) produces.
Output: `invoker/client.rs`, `config/{resolver,endpoint}.rs`, and their integration/unit tests.
</objective>
