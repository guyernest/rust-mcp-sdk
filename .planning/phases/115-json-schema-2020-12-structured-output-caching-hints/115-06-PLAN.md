<objective>
Project the caching hints onto the v2 wire — and strip them off the v1 wire — at the ONE shared
serialization chokepoint.

Purpose: SCHM-03, D-07, D-08, D-11, D-12. CONTEXT.md required the planner to first confirm that a
shared serialization chokepoint covering all the result types actually exists. **It does:**
`inject_v2_result_envelope` (`src/server/core.rs:1561`) is already era-gated, payload-gated,
object-gated, post-serialization, method-agnostic, twin-sited and separately tested. Four production
call sites carry every affected method.

Two things this plan must get right that are easy to get wrong:

1. **The v1 direction is not free.** `inject_v2_result_envelope` early-returns on non-v2, so a
   handler that sets `ttl_ms` on a `ListResourcesResult` and then serves a **v1** client would put
   `ttlMs` on the v1 wire — the exact leak D-11 forbids. The projection must therefore run on BOTH
   eras: ensure-on-v2, **strip-on-v1**.
2. **The method is not in scope at the chokepoint.** `request` is moved into
   `handle_request_internal` (`core.rs:3207`, `mod.rs:1654`) before injection runs, so the
   discriminator must be captured upstream while `request` is still borrowed.

Output: a `Cacheable` discriminator captured before the move at both dispatchers, a named projection
function inside the chokepoint, and unit coverage in the chokepoint's own test module.
</objective>

    response: &mut JSONRPCResponse,
    protocol_context: Option<&crate::types::protocol::ProtocolContext>,
    server_info: &Implementation,
    disposition: ResponseDisposition,
    owner: ReservedFieldOwner,
) {
    if !matches!(protocol_context.map(|c| c.era), Some(Era::V2)) { return; }   // v1 byte-identity

}
