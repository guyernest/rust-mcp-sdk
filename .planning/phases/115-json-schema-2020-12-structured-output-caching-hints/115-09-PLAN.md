`#[cfg(all(feature = "fuzzing", feature = "validation"))]`, exposing one function, `pub fn validate_bytes(schema_bytes: &[u8], instance_bytes: &[u8]) -> (bool, bool)`,

when either fails to parse, so the target does not degenerate into a JSON-parser fuzz) and returns
`(v1_conforms, v2_conforms)` by calling `schema_mismatch(schema, instance, Some(Era::V1)).is_none()`

`feature = "fuzzing"`, which is in neither `default` nor `full`, so the seam never reaches the shipped
public API; and that it deliberately returns BOTH verdicts so the fuzzer can hold a RELATIONAL
invariant rather than merely "did not panic".

**(c) The target.** Create `fuzz/fuzz_targets/fuzz_schema_draft_pin.rs`. Module doc in the
`fuzz_request_state.rs` voice: name the CLAUDE.md ALWAYS/FUZZ requirement and the plain
`cargo fuzz run fuzz_schema_draft_pin` invocation (no `+nightly` — it must match the Makefile

worth seeding (a draft-07-declared object schema, a 2020-12-declared one, an undeclared one, a schema
with `exclusiveMinimum: true`, a schema with array-form `items`, a schema with an external `$ref`,
deeply nested objects, and non-JSON bytes).

Use `arbitrary` to split the fuzz input into two byte slices (schema and instance). Invariants:
1. **Totality.** `validate_bytes` never panics for any input pair. A panic here is a remotely
   reachable unwind inside emit-time validation.
2. **The Finding-1 property.** When both parse and the schema declares a LEGACY `$schema` (draft-04,
   -06 or -07), the v2 verdict must NOT be more permissive than the v1 verdict — i.e. `v2_conforms`
   implies `v1_conforms` is not the assertion; the assertion is `!(v2_conforms && !v1_conforms)` for
   legacy-declared schemas. A hit means the 2020-12 pin accepted something the auto-detect rejected,
   which is the vacuous-validator bypass returning. State in a comment that 115-03's draft-07 unit
   test covers this for fixed examples and that this target covers it over arbitrary schemas.
   Skip this assertion when the schema fails to COMPILE under either era (both verdicts are then
   "mismatch" and the comparison is meaningless).
3. **No I/O.** Note in the module doc that an external `$ref` must remain a compile error rather than
   a fetch — the structural fence is `tests/v2_schema_tripwires.rs`, and the target simply must not
   hang.
