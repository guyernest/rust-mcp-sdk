<objective>
Consolidate the scattered error-code integer literals into ONE centralized version-gated module (VERS-06, structure-first) AND make that module the actual source of truth for the codebase's DOMINANT error-code surface: `error::ErrorCode` (a `pub struct ErrorCode(pub i32)` with 11 associated consts, referenced 210 times across 33 production files via `impl From<crate::Error> for JSONRPCError`). Also add the additive `ServerDiscover` variant to `ClientRequest` (VERS-04). All without touching the frozen `-32002` task-pending semantics or its locking test.

Purpose: The checker's Blocker showed `ProtocolErrorCode` (the C-style enum) is near-dead (zero external refs) while `error::ErrorCode`'s consts are the codes that actually reach the wire. If the new table were only mirrored against the dead enum, VERS-06 ("ALL protocol error codes live in ONE centralized version-gated constant table") and ROADMAP success criterion #5 would be FALSE — three parallel representations would remain. So `error::ErrorCode`'s consts DELEGATE to `error_codes::*` (Self(error_codes::NAME)); this centralizes all 210 call sites in one change without editing any of them, because they keep writing `ErrorCode::FOO` while `ErrorCode::FOO` now derives its value from the table. The frozen task-pending `-32002` stays separate from the spec's resource-not-found rename (a different semantic), and from `error::ErrorCode::UNSUPPORTED_CAPABILITY` (yet another `-32002` meaning that already exists — preserved by name, not reconciled). The `ServerDiscover` variant is the wire hook Plan 05 dispatches on. Everything is additive; the phase stays a 2.x minor (const VALUES are unchanged — only their definition site moves to a delegating expression, which is API-invisible to cargo-semver-checks).
Output: New `error_codes.rs` module (standard JSON-RPC + pmcp -320xx family + frozen v1 real, v2 TODO); `error::ErrorCode` consts delegating to it with a per-name consistency test; `ClientRequest::ServerDiscover` variant with an `#[non_exhaustive]` decision gated on `cargo-semver-checks`.
</objective>
