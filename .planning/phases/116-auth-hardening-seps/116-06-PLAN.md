<objective>
Close the gap that makes AUTH-01 bypassable, and make discovery follow the spec's ordered probe.

Purpose: RESEARCH Pitfall 1 is the most consequential finding in the phase. AUTH-01 compares the
callback's `iss` against `metadata.issuer` — but `OidcDiscoveryClient::fetch_discovery`
(`src/client/auth.rs:170-197`) fetches, checks status, deserializes and returns with NO comparison
between the document's `issuer` and the issuer used to build the URL. An attacker who can influence
discovery serves a document whose `issuer` is whatever they like, and the RFC 9207 comparison then
trivially succeeds against the attacker's own value. The spec says it in as many words: the `iss`
validation "provides no protection if the expected issuer was obtained from an unvalidated source."
Output: a bounded-read helper, the ordered probe, the §3.3 anchor check, and the RFC 9207 flag seam.
</objective>

used to build the URL and compare it, via `issuer_matches_metadata`, against the document's `issuer`

return an error naming both values and do NOT return the metadata. `fetch_discovery` is private, so
changing its signature to accept the expected issuer is free. Note the subtlety the probe introduces:
the value compared against is the ISSUER, not the candidate URL — all candidates for one issuer share
the same expected issuer.
