<objective>
Land SEP-2352's issuer-keyed credential storage as a trait (D-07/D-16) plus the two impls the SDK
ships, and fence the wasm-cleanliness of the whole pure tier in CI (D-06).

Purpose: `~/.pmcp/*.json` is not a viable credential store for ANY hosting target — `~` is unwritable
on Lambda and per-container on Workers and Cloud Run. "Issuer-keyed storage" shipped as a hardcoded
file path would be unusable by every platform pmcp targets. The trait is what makes the SDK serve the
durable-agent case (N servers, M providers, one user) and the single-user CLI with one seam. And
because the key INCLUDES the issuer, SEP-2352's "MUST NOT reuse credentials across authorization
servers" is true by construction, not by a check someone can forget.
Output: the store module, its two impls, `normalize_server_key`, and a wasm32 build fence.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pmcp process → on-disk credential file | Bearer and refresh tokens at rest, readable by any process running as the user if permissions slip |
| authorization server A credentials → authorization server B | The cross-AS replay SEP-2352 exists to prevent |
| platform implementor → CredentialStore trait | A trait that assumes a filesystem or an identity model pushes the SDK's choices into someone else's runtime |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-116-13 | Elevation of Privilege | cross-authorization-server credential reuse | mitigate | The store key INCLUDES the issuer, so a different AS is a cache miss by construction; asserted by the cross-issuer `load` test which returns `None` with no enforcement branch involved |
| T-116-14 | Information Disclosure | credential file readable by other local users | mitigate | Ported `write_atomic`: file `0o600`, parent `0o700`, tempfile-in-same-dir then rename; asserted by a unix permission test |
| T-116-15 | Information Disclosure | tokens leaked through a derived `Debug` | mitigate | `StoredCredentials` implements `Debug` manually with redaction; asserted by a test on `format!("{:?}", ..)` |
| T-116-16 | Tampering | schema-1 entry with no issuer re-keyed by guessing | mitigate | Unkeyable entries are DROPPED with a warning naming the server URL, never assigned to an issuer; the migration reports the dropped count |
| T-116-17 | Denial of Service | partial/torn credential file after a crash mid-write | mitigate | Atomic rename semantics from the ported `write_atomic`; `load` on corrupt JSON returns an actionable error rather than an empty store |
| T-116-18 | Tampering | future contributor adding a native dep to the ungated tier | mitigate | CI wasm32 build fence wired into the org-required `gate` aggregate |
| T-116-SC | Tampering | cargo installs | mitigate | Zero packages added; `tempfile` and `async-trait` are pre-existing; `Cargo.toml` diff is an acceptance criterion |

**At-rest encryption is explicitly OUT of scope** (CONTEXT § Deferred): the platform uses KMS, and a
plaintext `~/.pmcp` file is the status quo this phase does not change. Recorded, not silently omitted.
</threat_model>
