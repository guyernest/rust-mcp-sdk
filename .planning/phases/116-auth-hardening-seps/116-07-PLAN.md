<objective>
Bring the two server-side identity providers onto the same discovery behavior 116-06 gave the client:
the SEP-2351 ordered candidate probe, the RFC 8414 §3.3 issuer-anchor check, and bounded whole-body
reads (D-13, Pitfall 1, D-15).

Purpose: `generic_oidc.rs:394` and `cognito.rs:270` build the same wrong single URL by naive
concatenation that `client/auth.rs:137` did. Fixing one of three leaves a multi-tenant IdP broken in
the other two and leaves two more unvalidated anchors in the tree. `cognito.rs` is additionally worse
than its siblings: it does not even `trim_end_matches('/')`, so a trailing-slash issuer produces a
doubled slash today.

**Scope note:** this plan touches the server-side *identity provider* discovery clients only. It does
NOT touch the MCP resource-server side — no JWT validation change, no `ProxyProvider` change, no
`oauth_passthrough` change. A pmcp server behind a platform gateway is unaffected, which CONTEXT
states as a phase boundary.
Output: two providers on the shared derivation, with the Cognito TTL cache preserved.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| network / DNS → provider discovery document | Attacker-influenceable; the document's `issuer`, `jwks_uri` and endpoints feed downstream trust decisions |
| discovery document → Cognito TTL cache | A cached bad document persists a one-shot spoof for the whole TTL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-116-23 | Spoofing | provider discovery-document issuer | mitigate | RFC 8414 §3.3 comparison before the document escapes the fetch helper, in BOTH providers; each proven by a lying-issuer mockito fixture observed failing pre-fix |
| T-116-24 | Tampering | persistence of a spoofed document in the Cognito TTL cache | mitigate | Anchor-rejected documents are never written to the cache; asserted by a test that a second call re-attempts the fetch |
| T-116-25 | Denial of Service | oversized provider response body | mitigate | All whole-body reads routed through `collect_reqwest_body_within_cap` at 1 MiB; grep count of reqwest needles must be 0 in both files |
| T-116-26 | Denial of Service | multi-tenant IdP unreachable due to wrong discovery URL | mitigate | Shared `discovery_url_candidates` ordered probe; trailing-slash defect closed with an explicit test |
| T-116-SC | Tampering | cargo installs | mitigate | Zero packages added |
