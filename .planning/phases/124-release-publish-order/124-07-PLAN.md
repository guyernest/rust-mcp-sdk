the tag push to the user, and confirm each expected crate version live on crates.io — per

yanked but never unpublished, and the number is consumed forever. Meanwhile `release.yml`'s

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git tag -> registry token | The `v*` tag trigger is what grants `release.yml` the `CARGO_REGISTRY_TOKEN`. Anyone who can push such a tag can publish; the human checkpoint is the control. |
| crates.io API -> phase verdict | An untrusted remote response is the sole oracle for whether this phase succeeded. It is queried per crate, per expected version. |
| Actions run status -> phase verdict | Explicitly NOT a trust path: one job is known-broken and the publish job's skip guard makes success and silent-skip indistinguishable from its exit status. |
